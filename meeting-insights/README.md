# Meeting Insights Platform

A web platform that replaces the dense weekly **collections & sales meeting PDF** with a
database-backed, analytical dashboard. Data is entered through forms, processed and stored, and
surfaced as KPIs, charts, and an AI-written executive brief — covering **collection ageing risk
(90 / 60 / 30 days)**, **collection efficiency**, **sales & purchase (tons)**, and **quotation
conversion** across the two business units **MBS** and **MCORP**.

It ships seeded with the verified data from the meeting of **24-06-2025** (period 14–20 Jun 2025).

---

## Features

- **Per-user accounts with roles** — `admin` (manage users + data), `editor` (add/edit meetings),
  `viewer` (read-only). JWT auth, bcrypt password hashing.
- **Manual data entry** — forms for agent collections (ageing buckets × MBS/MCORP), sales/purchase
  tonnage by branch, and the quotation funnel. Outstanding totals are computed automatically.
- **Analytical dashboard** — KPI cards, ageing breakdown, agent collection-% leaderboard,
  quotation funnel, sales-by-branch, and a detailed agent table with risk highlighting.
- **AI insights** — an executive brief generated by Claude when `ANTHROPIC_API_KEY` is set,
  with a **deterministic computed fallback** so the platform is fully functional with no API key.
- **Week-over-week trends** — appear automatically once two or more meetings exist.
- **Self-contained** — Tailwind is pre-compiled and Chart.js is vendored; the app makes **no
  external CDN calls**, so it runs on locked-down / corporate networks.

## Quick start (local)

```bash
cd meeting-insights
./run.sh
```

`run.sh` installs dependencies, creates `.env`, seeds the database (printing the generated admin
password), and starts the server at <http://127.0.0.1:8000>.

To do it manually:

```bash
pip install -r requirements.txt
cp .env.example .env                 # set ADMIN_PASSWORD / ANTHROPIC_API_KEY if you like
python -m backend.seed               # creates DB + admin user + seeds the 24-06-2025 meeting
python -m uvicorn backend.main:app --reload
```

Log in with `admin` and the password from the seed output (or your `ADMIN_PASSWORD`).

## Configuration (`.env`)

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | SQLite by default; set a Postgres URL for cloud (e.g. `postgresql+psycopg://…`). |
| `JWT_SECRET` | Signing secret — **set a long random value in production**. |
| `JWT_EXPIRE_MINUTES` | Access-token lifetime (default 720). |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | Seed admin; blank password ⇒ randomly generated and printed. |
| `ANTHROPIC_API_KEY` | Enables Claude-written insights; without it, computed insights are used. |
| `AI_MODEL` | Claude model id (default `claude-sonnet-4-6`). |

## Deploying to the cloud

The data layer is plain SQLAlchemy, so going from local SQLite to a managed database needs **no
code change** — set environment variables on your host:

```
DATABASE_URL=postgresql+psycopg://user:pass@host:5432/dbname
JWT_SECRET=<long-random-string>
ANTHROPIC_API_KEY=<optional>
```

Then run `python -m backend.seed` once against the cloud DB and serve `backend.main:app` with any
ASGI server (uvicorn/gunicorn).

> Note: SQLite is not persistent on serverless platforms (e.g. Vercel) — use Postgres there.

## Project structure

```
meeting-insights/
  backend/
    config.py      — env-driven settings
    database.py    — SQLAlchemy engine/session
    models.py      — ORM models (User, Meeting, Collection, Sales, SalesRep, Quotation, Insight)
    schemas.py     — Pydantic request/response models
    auth.py        — JWT + bcrypt + role dependencies
    analytics.py   — pure metric functions (ageing, efficiency, leaderboard, trends)
    ai.py          — Claude insights + deterministic computed fallback
    main.py        — FastAPI app, routes, static mount
    seed.py        — seed admin user + meeting data from data/*.json
  frontend/
    index.html     — SPA shell
    app.js         — auth, router, dashboard / entry / trends / users views
    src.css        — Tailwind source (compiled to vendor/app.css)
    vendor/        — compiled app.css + vendored chart.umd.js (committed; no CDN at runtime)
  data/
    seed_2025-06-24.json   — verified data decoded from the original meeting PDF
  requirements.txt, run.sh, tailwind.config.js, package.json
```

### Rebuilding vendored assets (only if you change styles)

npm install

# Chart.js: cp node_modules/chart.js/dist/chart.umd.js frontend/vendor/chart.umd.js
```

## Data model notes

- A `Meeting` owns child rows: `Collection` (per agent), `Sales` / `SalesRep`, and `Quotation`.
- Meeting-level totals (outstanding / collection / sales / purchase) are **derived in
  `analytics.py`**, never stored — so the line items are the single source of truth.
- Collection ageing buckets are stored per unit: `d90_mbs`, `d90_mcorp`, … `other_mcorp`.

## API (all under `/api`, JWT bearer required except login)

| Method | Path | Role | Description |
|--------|------|------|-------------|
| POST | `/auth/login` | — | Obtain a token |
| GET | `/auth/me` | any | Current user |
| GET/POST/DELETE | `/users` | admin | Manage users |
| GET | `/meetings` | any | List meetings |
| POST | `/meetings` | editor+ | Create a meeting with line items |
| DELETE | `/meetings/{id}` | editor+ | Delete a meeting |
| GET | `/meetings/{id}/analytics` | any | Computed analytics bundle |
| GET | `/meetings/{id}/insights?refresh=` | any | AI / computed insights (cached) |
| GET | `/dashboard` | any | Latest meeting analytics |
| GET | `/trends` | any | Week-over-week series |
```
